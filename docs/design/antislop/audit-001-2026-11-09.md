# antislop audit 001 (2026-11-09)

Mode: AFTER. Branch `release/0.8.0` (commit c6a3b15).

Status: every item below is fixed. What changed is in the [follow-up](audit-001-2026-11-09-followup.md).

Scope: komando has no web UI, so this audit covers text only:

- README and the root docs
- `docs/features`, `docs/design` and `docs/design/gap`
- the agent texts (`guide.md`, `skill.md`, `skills/komando`)
- `CHANGELOG.md`
- the user-facing strings in Go (help text, hints, error catalog)
- the code comments in `internal/` and `cmd/`

Visual rules (contrast, layout, mobile, motion) do not apply.

How the audit ran: nine finders, one per area, then one skeptic per area who re-read every line and tried to refute each finding. The finders reported 69 findings. 57 survived the skeptics, and they are grouped into the items below. Em dashes were counted by script.

Priority follows the rule tier: Hard Gate = HIGH, Purpose-Gate = MEDIUM, Quality Locks = LOW.

Nothing has been changed yet. Pick the numbers you want fixed. Numbers you do not name stay untouched.

## HIGH: docs and claims that do not match the code (R-24, R-36, R-38)

1. **README.md:15 and SECURITY.md:26**, R-36. "The AI never sees them" / "never sees the values" is unconditional. Hiding only works for agents komando recognises (Claude Code, Codex, Cursor, Gemini CLI, or `KOMANDO_AGENT=1`). README:216-220 and AGENTS.md say so themselves.
   Fix: add that condition.
2. **docs/features/security-standards.md:100**, R-36. The page says "an agent without hooks gets the approval window and the masking", but only recognised agents get them. The LLM02 and LLM06 rows also overstate this.
   Fix: name the condition and mark those rows 🟡.
3. **docs/features/security-standards.md:33, :34, :79**, R-36. Three rows are more optimistic than the code:
   - :33 is ✅ even though it names a gap, which the page's own legend defines as 🟡.
   - :34 says "no 3DES, no PAP" without "by default". `--legacy-crypto` and `--allow-pap` exist.
   - :79 gives Token-Permissions ✅, but `cla.yml` sets write permissions at the top level.
4. **docs/features/output.md:74**, R-36. The page says "every code is in `komando schema`", but CERT_PROBLEMS, NXDOMAIN and SECRET_DESTINATION are missing from `errcodes.go`. `errcodes_test` also does not catch codes without an underscore or codes set through a variable.
   Fix: add the codes and widen the test.
5. **docs/features/output.md:51**, R-36. The page says "`error.hint` always says what to try next", but FAILED from `cluster run/exec` (cluster_run.go:370) and TIMEOUT (common.go:154) have no hint.
   Fix: add the hints, or a default hint in `out`.
6. **internal/cli/errcodes.go (the generated catalog)**, R-36. `komando schema` gives agents "the usual next step", but the generator pairs an example from one call site with a hint from another.
   Example at :50: DEPLOY_FAILED, whose hint says "check that ~/.ssh is writable". DB_CONNECT and other codes have the same problem.
   Fix: take each code's example and hint from the same call site, then regenerate.
7. **internal/cli/guide.md:288**, R-36. WRITE_FAILED is in the exit-code-1 row. A write on a server exits 5 (fs_write.go:147, errcodes.go:237). An agent that branches on this table gets it wrong.
8. **CHANGELOG.md:30**, R-36. The changelog says "every hint names a whole command you can run". Some hints do not, for example CONNECTION_LOST (job.go:239) and CRONTAB_UNREADABLE (modules.go:773).
9. **internal/cli/root.go:2 (package comment)**, R-36. The comment says "stdout is always JSON", "nothing ever prompts" and "everything is audited". None of the three is fully true:
   - a terminal gets text;
   - there are password prompts, the menu and yes-questions;
   - `update` run as root records nothing.

   Fix: scope the comment to agents and pipes.
10. **docs/design/network.md:150, :163, :178**, R-24. Three references are wrong:
    - `tunnel start --local 15432` fails. The right flag is `--port 15432`.
    - There is no `--bind` flag.
    - The code `IN_USE` does not exist. The real ones are `VPN_IN_USE` and `HOST_IN_USE`.
11. **docs/design/resources-and-db.md:177, :304, :342**, R-24. `db query --param` was replaced by `--arg`. `docs/usage.md` does not exist; the database docs are in `docs/features/databases.md`.
12. **docs/design/built-in.md:49, :80**, R-24. There is no `cluster cp` command. Copying goes through `cluster run -- cp`.
13. **docs/design/vision.md:158, :162**, R-24/R-38. Two rows in the import table are wrong:
    - The `aws` importer is described as putting the key into the vault. It actually uses an `aws_profile` and copies no key.
    - `termius` and `tableplus` are listed as import sources, but neither exists in `importSources`.
14. **docs/design/gap/README.md:41 and :134**, R-17/R-38. Two parts of the gap summary are out of date:
    - The PARTIAL count for vpn-secrets-platform is 40, but the report counts 39 plus 1 NOT PLANNED.
    - The "Biggest P2 themes" list is still called open work, but `vpn edit`, helm list/status/history, many-cluster views and MongoDB already exist.
15. **internal/netx/netx.go:3 (package doc)**, R-38. It says Tailscale and OpenVPN need an outside program. In this version both run inside komando (tsnet and its own OpenVPN client).
